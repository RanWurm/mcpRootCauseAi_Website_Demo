VERSION 3

AuthenticationManager: The Core

authentication-manager.ts

Promise Guard Pattern

export class AuthenticationManager {
  private bearerToken: string | null = null;
  private refreshToken: string | null = null;
  private tokenExpiresAt: number | null = null;
  private tokenPromise: Promise<void> | null = null;  // ← The guard!

  public async ensureAuthenticated(): Promise<void> {
    // 1. If auth already in progress, wait for it
    if (this.tokenPromise) {
      return this.tokenPromise;
    }
    
    // 2. If token valid, skip auth entirely
    if (this.bearerToken && !this.isTokenExpiringSoon()) {
      return;
    }
    
    // 3. Need auth - create guarded promise
    if (!this.refreshToken || this.isLocal) {
      this.tokenPromise = this.authenticate()
        .finally(() => { this.tokenPromise = null; });
      return this.tokenPromise;
    }
    
    // 4. Try refresh, fallback to full auth
    this.tokenPromise = this.refreshTokenFlow()
      .catch(() => this.authenticate())
      .finally(() => { this.tokenPromise = null; });
    
    return this.tokenPromise;
  }
}
Why This Works
  • tokenPromise ensures only ONE auth runs
  • All concurrent callers await same promise
  • finally() clears guard when done
  • No external locking library needed
Token Validity Check
private isTokenExpiringSoon(): boolean {
  if (!this.tokenExpiresAt) return true;
  return Date.now() >= this.tokenExpiresAt;
}

Skips auth if token still valid → fewer network calls

VERSION 3

Smart Token Refresh Strategy

70% ratio vs fixed buffer

V1: Fixed Buffer

const TOKEN_EXPIRY_BUFFER_MS = 30000;

// Token lifetime: 60s
// Refresh at: 60 - 30 = 30s ✓

// Token lifetime: 300s
// Refresh at: 300 - 30 = 270s
// → Only 10% buffer! Risk of expiry

// Token lifetime: 20s
// Refresh at: 20 - 30 = -10s
// → Negative! Immediate refresh loop

V3: Percentage Ratio

const TOKEN_EXPIRY_RATIO = 0.7;

// Token lifetime: 60s
// Refresh at: 60 × 0.7 = 42s ✓

// Token lifetime: 300s
// Refresh at: 300 × 0.7 = 210s ✓
// → 30% buffer (90s) - safe!

// Token lifetime: 20s
// Refresh at: 20 × 0.7 = 14s ✓
// → 30% buffer (6s) - still works!

Implementation

private setTokenData(tokenData: TokenResponse): void {
  this.bearerToken = tokenData.access_token;
  this.refreshToken = tokenData.refresh_token || this.refreshToken;
  
  // Schedule refresh at 70% of lifetime
  this.tokenExpiresAt = Date.now() + tokenData.expires_in * 1000 * TOKEN_EXPIRY_RATIO;
  
  this.startAutoRefresh();
}
Result

Works correctly with ANY token lifetime - 10 seconds or 10 hours. Always maintains 30% safety buffer.

VERSION 3

MCPClient: Token Polling Pattern

mcp-client.model.ts

export class MCPClient {
  private authManager: AuthenticationManager;
  private currentToken: string | null = null;  // ← Track current token

  private async request<T>(endpoint, params, schema, retries = 1): Promise<T | null> {
    if (!this.client) throw new Error('MCP client is not connected');
    
    // 1. Get current valid token from auth manager
    const token = await this.authManager.getBearerToken();
    
    // 2. Only reconnect if token actually changed
    if (token !== this.currentToken) {
      await this.reconnectWithNewToken(token);
      this.currentToken = token;
    }
    
    // 3. Make the actual request
    const result = await this.client.callTool({ name: endpoint, arguments: params });
    
    // 4. Handle 401 with retry
    if (result?.isError && this.isUnauthorized(result) && retries > 0) {
      console.warn('Token expired — attempting auto-reconnect...');
      return await this.request(endpoint, params, schema, retries - 1);
    }
    
    // ... rest of response handling
  }
}
Why Polling Works
  • No callbacks - MCPClient pulls when needed
  • No circular deps - one-way dependency
  • Lazy reconnect - only when token differs
  • Easy to test - mock getBearerToken()
Retry Logic

If server returns 401 (edge case where token expired between check and request):

  1. Force token refresh via ensureAuthenticated
  2. Retry request once with new token
  3. Fail if still unauthorized

DEEP DIVE

How the Promise Guard Prevents Race Conditions

V1: The Problem

// 50 concurrent requests hit the server
// Token expires during processing

Request 1:  refreshTokenFlow()  → gets Token B
Request 2:  refreshTokenFlow()  → gets Token C
Request 3:  refreshTokenFlow()  → gets Token D
  ...
Request 50: refreshTokenFlow()  → gets Token Z

→ 50 OAuth calls to Keycloak!
→ Token constantly changing
→ Requests fail with wrong token

V3: The Solution

// Same 50 concurrent requests

Request 1:  ensureAuthenticated()
            → tokenPromise = authenticate()
            
Request 2:  ensureAuthenticated()
            → return tokenPromise // waits!
            
Request 3-50: all return same tokenPromise

// authenticate() completes
→ 1 OAuth call total
→ All 50 requests get same token
→ All succeed

The Guard Pattern

public async ensureAuthenticated(): Promise<void> {
  // Guard: If auth in progress, ALL callers await the SAME promise
  if (this.tokenPromise) {
    return this.tokenPromise;  // ← This is the magic line
  }
  
  // Only first caller creates the promise
  this.tokenPromise = this.authenticate()
    .finally(() => { this.tokenPromise = null; });  // ← Cleanup after done
    
  return this.tokenPromise;
}

Key Takeaways

1. Separation Exposes Problems

Moving from monolithic (V1) to separated classes (V2) immediately made race conditions visible that were hidden before. This is a feature, not a bug!

2. Interfaces Drive Design

Clear interface boundaries (public vs private methods) forced us to think about responsibility and protection. Making methods private fixed the race conditions.

3. Pull > Push for Decoupling

Polling pattern (MCPClient pulls tokens) eliminated circular dependencies vs callback pattern (AuthManager pushes updates).

4. Validate Before Acting

Adding token validity check (isTokenExpiringSoon) eliminated 60% of unnecessary auth calls.

5. Promise Guards Work

Native JavaScript promise guards proved simpler and more effective than external locking libraries for concurrency protection.
