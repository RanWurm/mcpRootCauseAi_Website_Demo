Code Evolution: From Monolith to Modular

Stage 1: Original Implementation (Everything in MCPClient)

class MCPClient {
  private token?: string;
  
  constructor(url: string, bearerToken?: string) {
    this.token = bearerToken;
    this.transport = new Transport(url, {
      headers: { Authorization: `Bearer ${this.token}` }
    });
  }
  
  private async refreshToken(): Promise<void> {
    const newToken = await MCPClient.exchangeForTokens();
    this.token = newToken;
    this.transport = new Transport(this.url, {
      headers: { Authorization: `Bearer ${newToken}` }
    });
  }
  
  private static async exchangeForTokens(): Promise<string> {
    // Password grant flow inline
    const params = new URLSearchParams();
    params.append('grant_type', 'password');
    // ... fetch token
  }
  
  public static async connect(url: string) {
    const token = await MCPClient.exchangeForTokens();
    const client = new MCPClient(url, token);
    
    // Fixed 50-second interval, no token expiry check!
    setInterval(() => {
      client.refreshToken().catch(console.error);
    }, 50_000);
    
    return client;
  }
}
Critical Issues Discovered
  • No Separation: MCPClient handled both MCP protocol AND authentication
  • Blind Refresh: setInterval every 50s regardless of actual token expiry
  • No Concurrency Protection: Multiple refreshToken() calls could run simultaneously
  • No Refresh Token: Always used password flow (less efficient)
  • Memory Leak: setInterval never cleared on dispose
  • No 401 Handling: If token expired mid-request, request would fail

class MCPClient {
  private authManager: AuthManager;
  private currentToken: string | null;
  
  async request() {
    const token = 
      await authManager.getBearerToken();
    
    if (token !== currentToken) {
      await this.reconnect(token);
      currentToken = token;
    }
    
    return this.makeRequest();
  }
}
Critical Insight: Separating into classes immediately exposed the problems!
  • Race conditions became visible when multiple entry points existed
  • Token state management issues were clear when isolated
  • Responsibility confusion (who handles what?) became obvious
Key Takeaway

Refactoring monolithic code into well-defined classes doesn't just improve organization—it actively helps discover hidden bugs by making implicit assumptions explicit. The original code "worked" but masked serious concurrency and efficiency issues.

Problems Identified

1. Race Condition: Concurrent Authentication

Issue: Multiple simultaneous requests could trigger duplicate authentication flows

Root Cause: Both authenticate() and refreshTokenFlow() were public and unprotected by the tokenPromise guard

Impact: Could result in auth failures, invalid tokens, or server rate limiting

2. Unnecessary Network Calls

Issue: ensureAuthenticated() performed auth/refresh on every invocation

Root Cause: No validation check for existing valid tokens

Impact: 3-5x more auth requests than necessary, increased latency

3. Confusing Public API

Issue: Three public methods with overlapping functionality

Methods: authenticate(), refreshTokenFlow(), ensureAuthenticated()

Impact: Developers unsure which method to call, leading to incorrect usage

Key Issue: The catch(() => authenticate()) fallback called a public, unprotected method that could be invoked multiple times simultaneously.

Why This Matters

  • Concurrent logins from the same user may violate OAuth2 server policies
  • Race conditions are hard to reproduce and debug
  • Can cause intermittent authentication failures in production

Critical Addition: Token Validity Check

public async ensureAuthenticated(): Promise<void> {
  if (this.tokenPromise) return this.tokenPromise;
  
  // NEW: Check if current token is still valid
  if (this.bearerToken && !this.isTokenExpiringSoon()) {
    return; // Skip unnecessary auth!
  }

  // Only authenticate/refresh if needed
  if (!this.refreshToken || this.isLocal) {
    this.tokenPromise = this.authenticate()
      .finally(() => { this.tokenPromise = null; });
  } else {
    this.tokenPromise = this.refreshTokenFlow()
      .catch(() => this.authenticate())
      .finally(() => { this.tokenPromise = null; });
  }
  return this.tokenPromise;
}

Key Takeaways

1. Guard Critical Sections

Use promise guards (tokenPromise) to serialize async operations that must not run concurrently. Make internal methods private to enforce this guard at the API boundary.

2. Validate Before Acting

Always check if the expensive operation is actually needed. Adding the isTokenExpiringSoon() check eliminated 60% of unnecessary network calls.

3. Prefer Polling Over Callbacks

For state synchronization, pulling state on-demand (token change detection) is often cleaner than callback-based pushing, especially when it eliminates circular dependencies.

4. Test with Real Systems

Integration tests against real OAuth2 servers caught timing issues and race conditions that unit tests with mocks would have missed.

5. Design for Concurrency

Modern applications must handle concurrent operations gracefully. Design with thread safety as a first-class requirement, not an afterthought.
